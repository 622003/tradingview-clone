# CLAUDE.md — guide for continuing TradeView in Claude Code

This document is written for AI coding agents (Claude Code, Devin, etc.) and humans alike.
It captures the architecture, code conventions and recommended next steps so you can pick
the project up and ship the next feature without reverse-engineering it.

---

## TL;DR

- **Stack**: Next.js 14 App Router, TypeScript, Tailwind, Prisma + SQLite, `lightweight-charts`.
- **Auth**: custom session-based, in `src/lib/auth/session.ts`. NOT NextAuth.
- **DB**: SQLite locally (`prisma/dev.db`). Swap to Postgres by changing `provider` in
  `prisma/schema.prisma` and `DATABASE_URL`.
- **Market data**: generated by a deterministic seeded simulator (`src/lib/market/simulator.ts`).
  No external API.
- Run `npm run dev`, sign in as `admin`/`admin1234`.

## Conventions

### File organisation
- Pages live under `src/app/<route-group>/<route>/page.tsx`.
- API endpoints live under `src/app/api/<route>/route.ts` and use `NextRequest`/`Response`.
- Reusable components go in `src/components/<domain>/`.
- All cross-cutting logic lives in `src/lib/`.

### Imports
- Always use the `@/` alias for absolute imports (configured in `tsconfig.json`).
- Imports go at the **top** of every file — never inside functions/components.

### Styling
- Tailwind utility classes only. Avoid arbitrary values (`h-[600px]`) — use spacing scale.
- Dark theme is the only theme currently. Background is `zinc-950`, text `zinc-100`,
  accent blue is `blue-500` / `blue-400`.
- shadcn-style primitives in `src/components/ui/`. Compose them — don't re-implement.

### Server vs client
- Use **Server Components** by default. Sprinkle `"use client"` only when you need
  state, effects or browser-only APIs (the chart container, search dialog, etc.).
- Server components read directly from Prisma. Client components fetch via `/api/*`.

### API response envelope
Every API route returns `{ ok: true, data }` on success or `{ ok: false, error: { code, message } }`
on failure, using the helpers in `src/lib/api.ts`:

```ts
import { ok, handleError, parseJson } from "@/lib/api";

export async function POST(req: NextRequest) {
  try {
    const body = parseJson(MySchema, await req.json());
    // ...
    return ok(thing);
  } catch (e) {
    return handleError(e);
  }
}
```

### Dynamic API routes
API routes that read `request.url` query strings must opt out of static rendering:

```ts
export const dynamic = "force-dynamic";
```

## Architecture

### Auth (`src/lib/auth/session.ts`)
- Sessions are random tokens stored in a `Session` row and an `HttpOnly` cookie.
- `getCurrentUser()` resolves the user from the cookie, refreshes `lastLoginAt`,
  and rejects `BANNED`/`SUSPENDED` accounts.
- Use `requireUser()` or `requireAdmin()` in route handlers to gate endpoints.

### Market simulator (`src/lib/market/simulator.ts`)
- `generateCandles(ticker, interval, count)` returns OHLCV bars deterministically by
  hashing the ticker as the RNG seed (`mulberry32`).
- `priceQuote(ticker)` returns a synthesised live quote each call.
- To plug a **real** data feed, replace these two functions only — every consumer goes
  through them.

### Indicators (`src/lib/indicators/index.ts`)
Pure functions over `number[]`:
`sma`, `ema`, `rsi`, `macd`, `bollingerBands`, `vwap`. Easy to add more — just export
a new function and consume it inside `ChartView` (`src/components/chart/chart-view.tsx`).

### Database schema (`prisma/schema.prisma`)
Key models:
- `User`, `Session`, `ActivityLog`, `AuditLog`
- `Symbol`, `Candle` (one row per ticker x interval x time)
- `Watchlist`, `WatchlistItem`
- `Alert`
- `Idea`, `IdeaLike`, `IdeaComment`
- `NewsItem`
- `FeatureFlag`, `AppSetting`

After editing the schema, run:
```bash
npx prisma migrate dev --name <descriptive-name>
```

### Admin audit log
`recordAudit({ actor, action, target?, details? })` in `src/lib/admin/audit.ts`. Every admin
mutation in `src/app/api/admin/**` calls it.

### Feature flags
`getFlag(key, defaultValue)` in `src/lib/admin/audit.ts`. Add a flag by referencing it in code —
admins can flip it from `/admin/settings`.

## Common tasks

### Add a new technical indicator
1. Add a pure function in `src/lib/indicators/index.ts` (input: `number[]`, output: `(number|null)[]`).
2. Add a boolean field to `IndicatorConfig` in `src/components/chart/chart-view.tsx`
   and render it inside the main `React.useEffect`.
3. Add a `<SelectItem>` for it in `ChartPage` (`src/components/chart/chart-page.tsx`).

### Add a new page
1. Create `src/app/<group>/<route>/page.tsx`. Use the existing layouts:
   - `(public)/` is mounted under `AppShell` and works whether you're signed in or not.
   - `(app)/` requires auth (redirects to `/login`).
   - `admin/` requires `role === "ADMIN"`.
2. Add a nav entry in `src/components/layout/sidebar.tsx`.

### Add a new API endpoint
1. Create `src/app/api/<route>/route.ts` exporting `GET`/`POST`/etc.
2. Use `parseJson(MySchema, body)` for validation.
3. Use `requireUser()` / `requireAdmin()` for auth.
4. Return `ok(data)` or `handleError(e)`.
5. If the route reads query string params, add `export const dynamic = "force-dynamic"`.

### Add a new admin permission toggle
1. Add a column on `User` in `prisma/schema.prisma` (e.g. `canBacktest Boolean @default(false)`).
2. Migrate: `npx prisma migrate dev --name add-can-backtest`.
3. Expose it in `PATCH /api/admin/users/[id]` validation schema.
4. Add a `<Toggle>` in `src/app/admin/users/[id]/page.tsx`.
5. Surface it on the Profile page so the user can see it.
6. Check it in the relevant endpoint(s).

### Wire up a real data provider
Replace **just** these two functions:
- `generateCandles()` in `src/lib/market/simulator.ts`
- `priceQuote()` in `src/lib/market/simulator.ts`

The chart, watchlist, screener, alerts and admin features all flow through them.

## Roadmap / good next steps

These are **not implemented yet** but the codebase is structured for them:

- [ ] Real-time WebSocket feed (replace the 5-second polling in `chart-page.tsx`).
- [ ] Email/Telegram delivery for triggered alerts (currently alerts only set status
      to `triggered` — wire a worker).
- [ ] Drawings/annotations on the chart.
- [ ] Light theme toggle (root `<html>` is hardcoded `dark` in `src/app/layout.tsx`).
- [ ] Pagination on `/admin/users`, `/admin/audit`, `/news`, `/ideas`.
- [ ] Avatar uploads (`User.avatarUrl` exists, needs an upload route + storage).
- [ ] Comments on ideas (model `IdeaComment` exists but no UI yet).
- [ ] Two-factor auth (extend `Session` + add a `TwoFactor` model).
- [ ] OAuth providers (the auth layer is intentionally simple — drop in
      [`@auth/core`](https://authjs.dev/) if you want full social login).

## Gotchas

- **Don't shadow globals** with React state setters. We renamed `setInterval`
  to `setIntervalValue` in `chart-page.tsx` for exactly this reason.
- **API routes that read query strings must opt out of static rendering** with
  `export const dynamic = "force-dynamic"`. All current ones do.
- **`useSearchParams` in client pages** must be wrapped in `<Suspense>` (see `LoginPage`).
- **Banned users can still hold a valid session cookie**; `getCurrentUser()` rejects
  them anyway, but if you add a new auth helper, remember to check `user.status`.
- **Migrations are checked in**. After you change `schema.prisma`, always run
  `prisma migrate dev` so the SQL is committed alongside your code.

## When in doubt

1. Read `src/lib/api.ts` and `src/lib/auth/session.ts` — they explain how the rest
   of the app composes.
2. Grep for an existing similar feature (e.g. if adding a "Forums" feature, look at
   how Ideas is wired end-to-end: schema -> seed -> API route -> page -> admin moderation).
3. Run `npx prisma studio` to inspect the live database in the browser.

Happy hacking.
